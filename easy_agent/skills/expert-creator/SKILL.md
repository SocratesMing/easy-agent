# 专家创建器（Expert Creator）

把用户在对话里描述的"经验 / 领域 / 期望输出"沉淀成一个**可复用的专家 Agent**。
专家一旦创建成功，就会出现在「专家 · 技能 · 连接器」面板的专家 Tab 中，
用户点「使用」后由该专家以其专属人设与工作流回答。

## 一、适用场景

- 「帮我创建一个 XX 专家」「我想要一个专门做 XX 的顾问」
- 「把我下面这些经验做成一个专家」
- 「修改一下那个 XX 专家，让它更关注 XX」

不适用：创建**技能**（那是 `skill-creator`）、创建**定时任务**（那是 `create_scheduled_task`）。

## 二、工作流程

整个过程只调用 `save_expert` **一次**，所有字段一次性给全：

1. **确认名称**：从用户消息里提取专家中文名。用户没给名字时，根据其专长起一个
   2~20 字的名字（如「量化策略研究员」），并在回复里说明你起的名字。
2. **提炼需求**：把用户描述里的「经验 / 关注点 / 典型场景 / 期望输出」原样保留，
   不要改写成营销文案，也不要编造用户没说过的经历。
3. **产出配置**：按下文「字段规范」生成完整配置。
4. **调用 `save_expert`**：`action="create"`，把全部字段一次填好。
5. **如实汇报**：按工具返回的专家名称、ID、版本告知用户，并说明可在专家 Tab 中使用。

> 只调用一次工具。**不要让用户等你去猜、也不要分多次调用工具**——一次填全最快。
> 工具返回以 `错误：` 开头时，按提示修正后重试（例如重名要换名字）。

## 三、字段规范

| 字段 | 要求 |
|---|---|
| `name_cn` | 专家中文名，2~20 字，见名知专长 |
| `prompt` | 用户对专家的**原始需求描述**（提炼后的一段话，不超过 4000 字）。这是溯源与后续修改的依据，必须写清用户的经验与场景 |
| `system_prompt` | **核心字段**（300~800 字）。第二人称「你是……」撰写，含：角色定位、专业方法论、分析步骤、输出规范、与用户的交互方式。写成一段连贯的提示词，可以分段，但不要写成条目清单 |
| `description` | 功能描述，**不超过 300 字**，一段连贯的话，聚焦"这个专家能帮用户做什么"（用于卡片与详情页） |
| `skills_names` | **恰好 3 个**技能标签，每个 2~6 个汉字，体现最核心的专业专长（如 宏观投研 / 风险控制 / 因子分析）。金融领域必须用金融专业术语 |
| `tag_id` | 分类标签，**只能取自 `save_expert` 工具描述里列出的候选**（形如 `macro_research: 宏观投研`）。都不匹配时用 `other`。填中文标签名也可以，系统会自动归一 |
| `scenario` | 应用场景描述（80~200 字） |
| `capabilities` | 核心能力 3~6 条，每条一句话 |
| `workflow` | 工作流程 3~6 步，按执行顺序 |
| `boundaries` | 操作边界 / 禁止事项 2~5 条（如"不编造数据来源"、"不给出投资建议"） |
| `output_spec` | 输出规范 3~6 条（结论结构、数据标注要求、语言风格与长度） |
| `features_prompt` | 能力示例提示词 3~5 条，用户可直接点击使用的短句 |
| `name_en` | 英文标识名：小写字母/数字/连字符，3~40 字符，如 `quant-factor-researcher` |
| `profession_zh` / `profession_en` | 头衔中英文，如 `资深量化策略研究员` / `Senior Quantitative Researcher` |

**缺 `system_prompt` 会退化为「服务端再调一次模型生成」的慢路径**——请务必自己写全，
这样用户只需要等一次。

## 四、创建示例

用户说：*"帮我建一个债券投研专家，我做了 8 年信用债，关注城投和产业债的信用利差、
违约风险，希望输出结论式的判断，先给观点再给依据。"*

你应该调用 `save_expert`：

```
action: "create"
name_cn: "信用债投研专家"
prompt: "用户有 8 年信用债研究经验，关注城投债与产业债的信用利差、违约风险，希望输出结论式判断（先观点、后依据）。"
system_prompt: "你是「信用债投研专家」，一位有 8 年信用债研究经验的资深研究员。你擅长从主体基本面、行业景气、区域财政与再融资能力四个维度评估信用风险，并结合估值与利差水平给出配置判断。分析时先用一句话给出核心结论，再分点展开依据，明确区分【事实】【推断】【假设】，数据必须标明来源与时间。当信息不足时你直接说明缺口并列出需要补充的材料，不臆测财务数据。你与用户交流使用简洁、专业的中文，避免空话与营销式表述。"
scenario: "面向信用债投资与研究工作：评估个券/主体的信用风险与利差价值，辅助持仓决策与风险排查。"
capabilities: ["主体信用基本面评估", "城投与产业债利差分析", "违约风险与再融资压力排查", "个券估值与配置价值判断"]
workflow: ["明确研究对象与投资期限", "梳理主体基本面与区域/行业环境", "量化利差水平与历史分位", "识别风险点与触发条件", "给出结论式判断与跟踪要点"]
boundaries: ["不编造财务数据或评级信息", "不给出具体买卖建议", "信息不足时明确说明缺口"]
output_spec: ["先结论后依据，结论不超过三句话", "区分事实、推断与假设", "关键数据标注来源与时间", "使用简体中文，篇幅控制在 800 字内"]
features_prompt: ["帮我评估一下这家城投主体的信用风险", "这两个产业债哪个更有配置价值", "梳理一下这个主体的再融资压力"]
description: "具备 8 年信用债研究经验，从主体基本面、行业景气、区域财政与再融资能力四维评估信用风险，结合估值与利差给出结论式配置判断。"
skills_names: ["债券投研", "信用研究", "风险控制"]
tag_id: "credit_research"
name_en: "credit-bond-researcher"
profession_zh: "资深信用债研究员"
profession_en: "Senior Credit Bond Researcher"
```

## 五、修改专家

用户要改某个已存在的专家时：

1. **必须先拿到 `expert_agent_id`**（形如 `expert_xxx_1a2b3c4d`）。
   - 用户消息里带了 ID（从专家卡片「编辑」进来时前端会带上）→ 直接用；
   - 没带 → 请用户到「专家 · 技能 · 连接器」面板的专家 Tab 里找到该专家并点「编辑」，
     或把专家名称报给你、由用户确认 ID；
   - **不要猜 ID**，也不要为了找 ID 去读工作区文件。
2. 只改用户提到的部分，**未提及的字段保持原样**（原始需求 `prompt` 里补齐增量说明）。
3. `system_prompt` 等结构化字段要**给全**（基于原专家内容 + 本次修改），
   同样走一次调用完成的快路径。
4. 调用 `save_expert` 时 `action="update"`、带上 `expert_agent_id`。
   修改会写入新版本 `v{n+1}`，旧版本保留，运行中的会话不受影响。
5. 汇报时说明改了哪些点。

## 六、沟通规范

- 全程**简体中文**。
- 成功后如实告知：专家名称、专家 ID、版本号、修改/创建了哪些要点。
- **不要向用户暴露服务端文件路径**（版本目录、config.yaml、manifest.json 等）。
  用户只需要知道"专家已创建好、可以在专家 Tab 里使用"。
- 失败时把工具返回的错误原因转述给用户，并给出可执行的下一步
  （例如重名 → 请用户换个名字）。
