# 外汇投研专家（fx-investment-researcher）

> 公共专家（预置），只读。对应目录：`exports/preset_fx_investment/`

## 用途

把外汇研究问题转成可验证的数据查询与策略判断。K 线技术分析、做市交易监控、ESP/RFQ 订单查询与行情快照，统一通过 `fx-research`（外汇投研策略）技能调用两个 MCP 服务取数、交叉验证，并按技能报告骨架输出带来源编号的结论。

## 依赖技能与数据服务

本专家**不凭内置知识给行情**，取数只有一个入口：`fx-research` 技能。

```yaml
required_skills:
  - fx-research
```

技能封装有 MCP 服务（需在会话中已授权）：

- 技能来源：公共技能目录（`tools.skills_dir`），服务器版本含 `references/query-routing.md`、`references/forex-kline.md`、`references/fx-market-making.md`、`assets/report-template.md`
- 用户主动停用（技能被移到 `workspace/{user}/skills-disabled/`）时不再自动补装
- 服务未载入时，提示词要求「列明缺少的服务 / 工具与受影响的分析」；全部不可用时只交付资料缺口与取数计划，不生成看似已验证的结论

## 专家能力

1. 调度 `fx-research` 技能，通过 `forexqa`（K 线问数）与 `fxmmqa`（做市交易监控）两个 MCP 服务取数
2. K 线技术面分析：G7 货币对趋势、关键支撑阻力、形态与量能，说明信号在哪个周期成立
3. 做市交易监控：报价质量、点差、ESP/RFQ 订单流、库存与敞口，区分行情驱动与做市行为驱动
4. 四维驱动框架：货币政策与利差定中期方向、国际收支与资本流动定资金流、REER 与购买力平价定估值弹性、风险情绪定短期波动
5. 交叉验证：K 线方向与做市订单流不一致时并列呈现，不强行统一结论
6. 人民币专项：中间价信号、在岸离岸价差（CNY/CNH）、结售汇，区分央行引导与市场自发
7. 证据链管理：为每个来源建 `S1`/`S2` 编号，记录工具名、实际参数、数据日期、查询时间与记录 ID

## 期望输出

- 结构以技能 `assets/report-template.md` 为准，保留「资讯 / 结论 / 数据 / 分析 / 策略 / 风险与来源」骨架，不自行增删章节
- 默认中文 Markdown，沿用用户简繁体；需要文件时在工作区保存 UTF-8 Markdown 并给出链接
- 每个关键结论附来源编号，来源清单写清工具名、实际参数、数据日期、查询时间与记录 ID
- 专家只额外加三段：结论摘要、证据一致性说明（矛盾及原因）、风险与失效条件
- 结论注明「不构成具体投资建议」

## 使用边界

- 所有外汇研究请求必须走 `fx-research` 技能与 MCP 工具取数，不得用内置知识或记忆中的行情给点位、涨跌幅、点差、成交量与订单数据
- 不编造行情与数值；工具未返回就不给数字，也不给「大概在这个位置」这类模糊替代
- 多来源矛盾时列出矛盾与可能原因，不用「综合来看」强行统一
- 只做外汇市场，范围外的问题说明不做，不套用外汇口径代做
- 不提供具体交易指令与杠杆操作建议，不承诺收益；汇率判断必须写明关键假设与失效条件
- 提示汇率双向波动风险，涉及新兴市场货币时提示流动性与管制风险

## 如何新增 / 修改公共专家

在 `exports/` 下新建一个目录（目录名建议与 `expert_agent_id` 一致），采用版本布局：

```
exports/{expert_agent_id}/
├── active               # 版本指针（内容为版本号，如 1）
└── v1/
    ├── config.yaml      # 必填：name_cn / tag_id / description / skills_names / features_prompt ...
    ├── manifest.json    # 建议：生成元数据
    ├── {name_en}.md     # 必填：提示词正文（除 README.md 外唯一的 .md）
    └── README.md        # 可选：面向使用者的说明
```

升级时新增 `v2/` 并把 `active` 改为 `2`；详见 `docs/expert-agent-solution.md`。
