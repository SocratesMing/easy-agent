# 因子研究专家（factor-research-expert）

> 公共专家（预置），只读。对应目录：`experts/preset_factor_research/`

## 用途

把用户的一句投资逻辑翻译成可执行规格，调度 `factor-creator` 技能完成因子生产全流程，并对产出做可信度校验；技能不覆盖的审查、组合与方案设计由专家独立完成。

## 专家能力

1. **需求五要素校验**：因子名称、创建逻辑、回测参数、是否调优、回测区间；缺项一次性问齐并停下，可从表述无损推断的不追问，可安全默认的用缺省口径并标注来源
2. 调度 factor-creator 技能完成因子创建、信号编写、回测、评估、参数调优与因子详情输出
3. 把口语化需求转成可执行的因子规格：类型、方向、market/contract/timeframe、调仓方式与评估口径
4. 校验技能产出的可信度：产物是否落地、参数是否与「需求回执」一致、评估结论是否有数据支撑
5. 存量因子代码审查：未来数据风险、计算效率瓶颈、命名与目录规范，逐个指出位置
6. 多因子组合：相关性检查与正交化，等权 / IC 加权 / 回归加权的选择依据与实现
7. 研究方案设计：从研究目标出发给候选因子清单、验证路径与失败判据

## 期望输出

- 创建类：先给「需求回执」（五要素 + 推定与默认 + 待确认），再给 做了什么 → 产物路径 → 关键参数 → 回测与评估的关键结果 → 风险与下一步
- 代码审查类：逻辑正确性 / 未来数据风险 / 计算效率 / 命名规范 四项清单，各给具体位置
- 组合与方案类：先给结论与选择依据，再给实现或清单，含相关性与共线性判断
- 所有数值须来自技能真实执行或用户提供；结论注明「不构成投资建议」

## 五要素与缺省口径

| # | 要素 | 缺省值 |
|---|---|---|
| 1 | 因子名称 | 无可从逻辑无损推出时追问，不自拟 |
| 2 | 创建逻辑 | 必须由用户给出（字段 → 变换 → 窗口 → 方向） |
| 3 | 回测参数 | 调仓跟随 timeframe；截面用 RankIC+5 组分层、单合约用 时序 IC+多空净值；成本 A 股双边万三 |
| 4 | 是否调优 | 默认不做，除非用户要求或评估显示参数高度敏感 |
| 5 | 回测区间 | **没有缺省值，必须问** |

## 使用边界

- 不手写因子生产代码（审查、组合、方案设计所需的示例代码除外），生产动作一律交由 factor-creator 技能完成
- 不输出任何未经真实计算的回测数值（IC、年化、夏普、最大回撤），只给方案、代码或解读用户提供的真实结果
- 不编造 SDK 函数名、字段名、表名与路径，无法确认时写「需确认」并请用户提供样例
- 严禁未来数据：不用负数位移、不用报告期对齐财务数据、不用当日收盘价生成当日可执行信号
- 主动提示过拟合、数据窥探、幸存者偏差、多重检验四类风险

## 依赖技能：factor-creator

本专家**不手写因子生产代码**，创建 / 信号 / 回测 / 评估 / 调优 / 因子详情统一交由 `factor-creator` 技能执行。因此它有一个硬依赖：

```yaml
required_skills:
  - factor-creator
```

- 技能来源：公共技能目录（`tools.skills_dir`，默认 `./skills/factor-creator/`）
- 安装方式：用户在技能中心「添加」，或**首次使用本专家时由后端自动补装**到 `workspace/{user}/skills/`
- 用户主动停用（技能被移到 `workspace/{user}/skills-disabled/`）时不再自动补装
- 技能缺失或执行失败时，专家按提示词「注意事项 · 降级」处理：明确列出缺失项，不产出半成品因子

技能侧覆盖范围：创建 → 回测 → 评估 → 参数调优 → 输出因子详情；细节文档在技能的 `references/`（`polars_expressions`、`indicator_formulas`、`debugging_guide`、`testing_guide`、`node/`）。

专家独立承担技能不覆盖的三类工作：存量因子代码审查、多因子组合、研究方案设计。

## 文件说明

| 文件 | 说明 |
| --- | --- |
| `config.yaml` | 卡片/详情页展示字段与元数据（分类标签、技能标签、示例问题等） |
| `manifest.json` | 生成元数据（版本、提示词文件名、生成时间等） |
| `factor-research-expert.md` | 专家提示词正文（召唤时注入系统提示词末尾） |
| `README.md` | 本文件，面向使用者的说明 |

## 如何新增 / 修改公共专家

在 `experts/` 下新建一个目录（目录名建议与 `expert_agent_id` 一致），采用版本布局：

```
experts/{expert_agent_id}/
├── active               # 版本指针（内容为版本号，如 1）
└── v1/
    ├── config.yaml      # 必填：name_cn / tag_id / description / skills_names / features_prompt ...
    ├── manifest.json    # 建议：生成元数据
    ├── {name_en}.md     # 必填：提示词正文（除 README.md 外唯一的 .md）
    └── README.md        # 可选：面向使用者的说明
```

升级时新增 `v2/` 并把 `active` 改为 `2`；详见 `docs/expert-agent-solution.md`。
