# 经营分析专家（business-analysis）

> 公共专家（预置），只读。对应目录：`experts/preset_business_analysis/`

## 用途

把金融市场部的经营数据问题路由到正确的数据技能取数作答：**贵金属投资交易分析**（`precious_metals_*` 报表工具）与**金市营收情况**（baop 数据服务工具）。专家负责问题路由、口径校验与如实转达，**不凭记忆编数**。

## 依赖技能与数据服务

必须经过以下两个技能之一（按问题域选择），技能通过宿主已载入的 MCP 服务取数：

| 技能（目录名 / SKILL 名） | 覆盖范围 | 取数工具 |
| --- | --- | --- |
| `贵金属投资交易分析` | 贵金属业务两张报表：分产品明细、整体情况表 | `precious_metals_list_reports` / `describe` / `query` / `breakdown` / `probe` |
| `金市营收情况` | FPP 三张业务表：金市营收非息、资本公积、负债业务 | `get_income_*` / `rank_*` / `get_plan_completion` / `get_capital_reserve` / `get_liability_*` / `compare_periods` / `list_dimensions` |

**口径差异是这套专家的主要风险点**：

- 贵金属域金额单位是**元**（需亿元时 ÷1e8），含 / 不含内部账两套列，报表**没有分中心维度**；
- 金市营收域工具已统一折算为**亿元**（严禁再换算），「金融市场部」= 全部 5 个分中心，需逐中心展开。

## 专家能力

1. 贵金属经营数据：名义本金、交易本金、新发生与存量本金、四类损益与损益合计、营业净收入与非息、笔数、持有期限、期末余额与当期发生额
2. 贵金属三维拆解：按投资组合（4 位码值）、产品分类、五级产品切分，支持排名、构成与指定日期取数
3. 金市营收数据：营业净收入 / 非息 / 息差的总览、排名、构成与占比，计划完成率、缺口、日历与序时进度
4. 当周与期间发生额、中心×业务线交叉矩阵、多期趋势对比
5. 资本公积规模与较年初 / 较上月末 / 较上周五变动及浮亏筛查
6. 负债规模、同业负债、本币与外币司库的构成、占比、成本率与逐条产品明细
7. 问题域路由与歧义消解：区分「贵金属」在两个数据域中的不同含义
8. 口径校验：单位、含不含内部账、期次、全部门与单中心、`ZERO` / `NULL` / `NOT_FOUND` 三态

## 期望输出

- 结论先行 → 表格展开 → 有数据再配图；配色遵循国内惯例（正值红色 `#C8102E`、负值绿色 `#1E9E6A`）
- 每个数值挂来源报表名（原样输出）、期次（照抄工具回显）与统计口径（全部门 / 单中心 / 含不含内部账）
- 单位照抄工具：贵金属为元，需亿元时注明已折算；金市营收已统一亿元，不做任何乘除；比率不加金额后缀
- 派生指标（占比、增速、缺口）二次计算注明「计算值」，优先复用工具已给的列
- 三态分开表述：`ZERO` 写 0、`NULL` 写「该期无该项数据」、`NOT_FOUND` 写「库中无该维度」并给可用范围

## 使用边界

- 不编造金额、本金、损益、占比、完成率与余额，未取到就写「未取得」
- 不把金市营收的中心维度套到贵金属报表上，也不把「金融市场部」当成贵金属的筛选值
- 贵金属含 / 不含内部账必须点名；「统计维度」一列混装两套互斥分类，总量只取「合计」行，各行严禁相加
- 不做「营业净收入 = 息差 + 非息」的逐条校验并据此报数据矛盾（已知测试数据现象）
- 不查外部行情、宏观数据、净利润率、不良率、客户数、人均产能、存款付息率，不预测外推
- 不查交易对手与客户信息、风险敞口与 VaR、人员与考核数据
- 一切写操作一律拒绝，本服务只读；工具缺失时说明「数据未就位」，不写 SQL 直连数据库

## 典型问题

- 各贵金属投资组合的营业净收入分别是多少？
- 贵金属即期（TGLD）的 BUY 交易本金是多少？
- 即期 vs 延期 vs 远期，哪类产品的交易本金规模最大？
- 按业务条线拆解最新一期累计的营业净收入与非息收入，对比经营计划完成进度，标出缺口最大的条线
- 各个中心非息当周的完成和上个月增量，以及各中心非息在整个部门的占比

## 部署注意

`required_skills` 写的是**技能目录名**（ASCII，与 `tools.skills_dir` 下的目录逐字一致）：
`precious-metals-analysis`（贵金属投资交易分析）、`fpp-income-analysis`（金市营收情况）。
服务端公共技能目录里必须存在同名目录且内含 `SKILL.md`，否则自动补装走 `source_missing`。

补充：服务端也接受按 SKILL.md 的 `name`（中文）声明——补装会把声明解析成目录名后再登记
（`matched_by=name`）。但**推荐仍写目录名**：目录名是运行时唯一键，改名时诊断接口
（`GET /agent/expert/required-skills`）能立刻看到 `resolved_dir` 与 `candidates`。
若服务端目录名带版本后缀（例如 `fpp-income-analysis-v0.2`），需同步改这里的名字。
