# 金融市场部经营分析问答（baop 数据服务）

> 本 Skill 是**通用型**：不依赖某个库当前装了多少数据、有哪些日期。
> 期次、维度、指标、可用范围**一律以工具实时返回为准**，本文不写死任何具体日期或期数。

**取数唯一通道 = 本数据服务的查询工具**，直接调用即可，工具清单见第三节。

> **数据未就位的情形**：当前环境看不到下列查询工具、或工具调用返回连接/执行错误时，
> **如实告知用户「数据未就位」并说明原因**；**不要凭记忆作答、不要推测、
> 不要改走命令行或自己写 SQL 直连数据库**。

**所有数字必须来自工具返回，严禁凭记忆或推测编造。**

## 一、数据范围与口径

> **三表源单位各不相同（业务方已确认，勿再变更）。** 工具层逐表折算后统一输出**亿元**。

| 表 | 业务板块 | 源表底层单位 | 折算 | 工具输出 | `unit` 字段 |
|---|---|---|---|---|---|
| `fpp_fin_mkt_bizline_income_sum_t1`（T3） | 营业净收入 / 非息 / 息差 | **万元** | ÷ 1e4 | **亿元** | `亿元` |
| `fpp_core_cap_rsrv_t1`（T1） | 资本公积（可供出售账户） | **亿元** | 原值 | **亿元** | `亿元` |
| `fpp_whl_liab_biz_situ_t1`（T2） | 负债规模 | **元** | ÷ 1e8 | **亿元** | `亿元` |

> 三张表**不是**统一的万元，别按同一系数口算。**T3 除以 1 万、T1 不动、T2 除以 1 亿**，
> 才是各自的亿元值；工具已做完这一步，正常取数**不需要**自己算。

**必守规则**

1. **单位换算已写在工具里，不要自己换算。** 三表源单位不同（**T3 万元 / T1 亿元 / T2 元**），
   工具已逐表折算并统一输出**亿元**；若工具已给亿元，直接引用，**严禁再对结果做任何乘除**
   （T1 再除会小 1 万倍，T2 再乘会大 1 亿倍，且从数字上看不出来）。
2. **单位不只看金额，非金额字段不许加"亿元"后缀：**
   | 类别 | 单位 | 出现在 |
   |---|---|---|
   | 完成率 / 序时进度 / 日历进度 / 各类占比 | **%** | T1 各处、`comp_rate`、`tm_prog`、`*_per` |
   | 成本率 | **%** | T2 `cost_rate` |
   | 成本率变动（`cost_*` 基准、明细 `vs` 的成本率变动列） | **百分点（pp）** | T2 概览 / 明细 |
   | 增速（`growth=True`、明细四个增速列） | **%** | T1、T2 |
   | 加权完成率差值（如「完成率−日历进度」） | **pp** | `get_plan_completion_tool` |
3. **数据是日频的**（每天一期）。**未指定日期时，缺省取最新可用期次**；工具会在返回里回显
   实际使用的期次（`period_resolved` / `stat_date` / `summary` 首句），**照抄即可**。
   **不要自己拼具体日期**，除非用户明确指定。
4. **不要把 `ZERO`、`NULL`、`NOT_FOUND` 混为一谈**（三态）：
   | 态 | 含义 | 正确表述 |
   |---|---|---|
   | `ZERO` | 真实为零（该维度该期确实没发生） | "**0 亿元**" |
   | `NULL` | 该字段无数据（如无可比上期） | "该期无该项数据" |
   | `NOT_FOUND` | 条件没命中（维度/期次不存在） | "库中无该维度/期次，可用范围为…" |
5. **两张日期字段是两个概念，别串。** 数据日期 `DATA_DT` 是跑批快照日（工具恒定取最新），
   业务日期（T3 为 `BIZ_DT`、T2 为 `DATA_PRDC_DT`）才是 `period` 参数能传的值。
   用户说"某天的数"通常指**业务日期**；用户问"数据更新到什么时候"要**两个都说**。
6. **字段语义与码值以数据字典为准。** 不同表的同名字段含义可能不同，跨表比较前必须核对码值，
   **不可想当然**。
7. **只读。** 任何新增 / 修改 / 删除 / 建表诉求一律拒绝，并说明本服务为只读查询。

## 四、参数填充约定（这决定链路对不对）

1. **日期不要自己传。** 缺省即为最新可用期次，工具会自动回显。只有用户**明确指定日期**时才传 `period`，
   且传的是**业务日期**。⚠️ `n_periods` 是**期数**不是月份，日频下 1 期 = 1 天；工具内部限幅 2–12 期。
   用户说"近一季度 / 近半年"时**不要**换算成 90/180 去传，按实际可得期数回答并说明覆盖范围
   （工具会给"需 N 期，实际可用 M 期"的降级说明，照抄）。
2. **维度不要直接传用户原话。** 用户表述往往不精确（简称、别名、口语、错别字），
   **必须先取码值清单**（`list_dimensions_tool(dimension=…)`），**对照码值找到最符合的一项**，
   再按标准码值传参；没有把握时把候选项列给用户确认，**不要猜**。
   （工具内部还会做一次标准化并在 `resolved` 中回显，但**先按码值对齐**能显著减少查空与歧义。）
3. **同一个词可能落在不同维度**（中心 / 业务线 / 负债大类 / 业务类别 / 币种），
   传参前先确认用户指的是哪个维度；定不了就**问用户**，不要随便挑一个。
   例：「同业」= 负债大类 `同业负债`，不是中心；「外汇」= 业务线 `外汇交易业务`，不是币种；
   「贵金属」= 业务线 `贵金属及商品交易业务`，不是产品。
4. **`core` 与 `biz_line` 是两个不同维度，不要同时传。** 两者都不传即按中心级汇总
   （等价于部门口径）。部门名「金融市场部」也是合法的 `core` 取值 = 全部中心。

   **「金融市场部」= 全部 5 个分中心**（做市交易 / 外币资产管理 / 客户 / 投资管理 / 资金管理中心）。
   库里没有独立的「部门」维度，部门口径就是这 5 个中心的集合。以下写法一律按全部门处理：
   **金融市场部、金融市场部门、金融市场、分行金融市场部、中信银行金融市场、资金业务部、
   全部门、整个部门、全部中心、各中心合计、咱们部门、我们部门**。
   工具侧 `DEPARTMENT_MAP` 已内置该映射（值为 `ALL`），`_match_department()` 按
   「全等 / 输入包含部门名 / 部门名包含输入」三路匹配，能容忍上述多数写法；
   命中后自动全中心汇总并给出加权完成率，`resolved` 里会回显实际生效的口径，引用时以它为准。

   **若工具仍返回 `NOT_FOUND`（说明该说法没被映射到）**：**不要**改用某个中心去凑，
   直接**不传 `core`**（缺省即全部门汇总）重新查一次，并在回复里说明「已按全部门口径统计」。

   > **中心名不会被误判成部门**（工具侧已保证）：`资金管理中心`、`投资管理中心`、`做市交易中心`、
   > `外币资产管理中心`、`客户中心` 以及它们的简称（`资金`/`投管`/`做市`/`外币资管`/`客户`）
   > 一律按**单中心**处理，不会因为名字里带「资金」「管理」就被当成整个部门。
   > 换句话说：说中心就是中心，说部门才是部门，两边不会打架。

   > ⚠️ 问「部门/金融市场部」时**不要**只答一个中心，也**不要**把某个中心当成部门；
   > 但要同时说清是**全部门汇总**口径，别让用户误以为是单中心数据。
   > 若用户先问部门总量、再问各中心，第二问要**逐中心列全 5 个**，不能只挑高的几个。
5. **`top_n` 只影响展示行数**，工具摘要里会同时给「共 N 个」与「展示 M 个」，
   引用时两个数都要说清。

## 五、派生指标怎么算（工具不直接给时，按这里算并注明）

工具返回的是**原子指标**。下列派生指标需在工具结果上二次计算，**回复里注明"（计算值）"**：

| 派生指标 | 算法 | 典型问法 |
|---|---|---|
| **占比** | 单项 ÷ 合计 × 100% | "占多大比重""各自占比多少" |
| **增速（多期）** | 末期 ÷ 首期 − 1 | "近三期谁增长最快" |
| **累计变化** | 末期 − 首期 | "三期累计变化了多少" |
| **计划缺口** | 计划/目标 − 实际累计（同一期、同一对象） | "离全年计划还差多少" |
| **两对象对比** | 用 `rank_income_tool(by='core')` 一次取全，再取两行对比 | "A 和 B 谁贡献更大" |
| **同类业务线聚合** | `rank_income_tool(by='biz_line', top_n=0)` 取全量后按名称归并 | "利率相关的业务一共多少""跨境类业务怎么样" |
| **完成率 vs 时间进度** | `get_plan_completion_tool` 已直接给「完成率−日历进度」列 | "完成率低于序时进度吗" |

> **优先复用工具已给的列，不要另起炉灶**：
> - `get_plan_completion` 已给「缺口 / 完成率（加权）/ 日历进度 / 完成率−日历进度」；
> - `get_income_detail` 已给「营业缺口 / 非息缺口 / 营业完成率 / 非息完成率 / 非息序时进度」；
> - `get_income_overview` 已给「非息占营业比」；`get_liability_overview` 已给「余额占比 / 年均余额」；
> - `get_capital_reserve(growth=True)` / `get_liability_detail(growth=True)` 已给源表预计算增速。
>
> 归并同类业务线时，**基数用工具给的合计口径**，且必须说明归并了哪几项、是否完整。

## 六、返回处理（照做，不要改写）

信封字段：`shape` / `title` / `summary` / `unit` / `stat_date` / `table` / `chart` / `notes` /
`period_resolved` / `resolved` / `candidates` / `result_state`。

| 字段 | 怎么用 |
|---|---|
| `result_state = NOT_FOUND` | 报"库中无此维度/期次" + 给候选清单，**不要外推、不要用别的日期顶替** |
| `result_state = ZERO` | 说明"真实为 0"，**不要**写成"无数据" |
| `result_state = NULL` | 说明"该字段无数据"，**不要**写成 0 |
| `result_state = AMBIGUOUS` | **不取数、直接反问**，把 `candidates` 里的候选列给用户，**不要取第一个** |
| `candidates` **非空** | 同上，反问；此时 `table` 为空，手上没数就没法编 |
| `resolved` 非空 | 在回复里**回显映射**：「已按【X】查询」（用户看得见，可纠正） |
| `period_resolved` / `stat_date` | **照抄，不要改写**（期次已写进 `summary` 首句） |
| `notes` | **照抄关键条目**，尤其带 ⚠️ 的降级声明与口径说明 |

> `summary` 是**口径最稳的字段**（含期次、合计、最高/次高、降级说明），优先引用它；`table` 用于展开明细。
> **`result_state != OK` 时 `table` 为 `null`**，此时**不要给任何数字**。

## 七、呈现规则

1. **结论先行** → 表格 → 有 `chart` 时再出图。
2. 图表**不要**把原始图表配置原样贴给用户。数据取 `table.rows`（与图同源且更完整），
   图型看 `chart.series[].type`（`bar` 横向条形/柱状、`pie` 构成、`line` 趋势），按当前环境支持的
   绘图能力转译。
3. **配色遵循国内惯例：正值红色 `#C8102E`、负值绿色 `#1E9E6A`**（工具已在 chart 里写死）。
4. **单位一律照抄工具的 `unit` 字段与列名后缀，不要自己换算，也不要统一改写。**
   三张表源单位不同（T3 万元 / T1 亿元 / T2 元），工具已逐表折算为亿元，所以**金额列都是亿元**；
   但**比率类列不是**——完成率、序时进度、日历进度、占比、成本率、增速是 **%**，
   成本率变动与「完成率−日历进度」是 **百分点（pp）**。这些**不许加"亿元"后缀**。
   金额保留 2 位小数。
5. **综合体问题**（"哪个中心最需要关注""有没有风险点"）**必须多工具编排**再下结论：
   例如 完成率（`get_plan_completion`）+ 收入规模（`rank_income`）+ 趋势（`compare_periods`）三条合看，
   并**说明判断依据来自哪几个指标**，不要凭单个数字臆断。
6. **完成率不要手工平均。** 工具已按 Σ实际÷Σ计划 加权；若自己写公式，必须保证是加权口径，
   否则与工具的数值不一致会被当成数据错误。
7. **`get_income_matrix` 只筛单个中心时，表里只有 1 行**（没有「合计」列、也没有底部「合计」行，
   因为那一行本身就是合计）。此时：
   - **不要**问「那合计是多少」——`summary` 里已经给了，就是那一行的总和；
   - **不要**把该行任意一格当成"中心合计"，每格都是单条业务线；
   - 铁律：**单中心时"合计"不等于任何一格**，引用时写「该中心合计 X 亿元（17 条线之和）」。
8. **`get_liability_overview(lib_cls='本币司库' / '外币司库')` 只有 1 条汇总记录**
   （源表对这两个大类不做产品级拆分）。此时 `summary` 会写「源表对该大类只有这一条汇总记录
   （无产品级拆分）」——**照着说**，不要写成「最大产品是…」，也不要追问「那有哪些产品」。
9. **⚠️ 逐条业务线上「营业净收入 ≠ 息差 + 非息收入」。** 这是已知的数据生成问题
   （测试数据里息差是独立随机列），**只有合计层面三者能对上**。
   引用时只读列值，**禁止**用「息差 + 非息」去反推营业净收入，也**禁止**在回复里做这种校验并报"数据矛盾"。

## 八、边界与拒答

- **期次超出可用范围**：工具返回 `NOT_FOUND` 并给出可用期次清单。
  如实报边界并给可用期次，**不要外推、不要插值**，也不要用别的日期顶替。
- **维度或条件命中不到**：如实说明并给出候选清单（`candidates`），请用户确认，**不要编造数据**。
- **趋势期次不足**：某个对象只有 1 个可用期次时，工具会直接报 `NOT_FOUND` 说明"无法比较"。
  这不是"持平 0.00"，**不要给假趋势**，改用对应的单期工具。
- **超出数据域**：净利润率 / 不良率 / 客户数 / 人均产能 / 存款付息率 / 外部行情 / 预测外推
  → 明确拒答并说明库中有什么。
- **写操作一律拒绝**（新增/修改/删除/建表；"把计划调高 10% 重新算"这类也拒答）。
- **数据服务不可用时**：如实告知「数据未就位」并说明原因，**不要凭记忆作答、不要推测，
  也不要改走命令行或自己写 SQL 直连数据库**。
