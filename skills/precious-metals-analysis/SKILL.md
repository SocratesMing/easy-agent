# 贵金属投资交易分析

**取数唯一通道 = precious-metals MCP 的 5 个工具**（`precious_metals_*`），直接调用即可。
**所有数字必须来自工具返回，严禁凭记忆或推测编造。**

> **数据未就位的情形**：看不到 `precious_metals_*` 工具、或调用返回连接错误时，
> **如实告知用户「数据未就位」并说明原因**（常见原因是工具未接入、或报表服务不可达）；
> **不要凭记忆作答、不要推测、不要改走命令行抓页面或自己写解析。**

**本文件已不再附带任何静态字段清单。** 指标有哪些、维度有哪些取值、某字段什么含义，
**一律现场调 `precious_metals_describe` 查**，不要凭本文或记忆作答——报表增删品种后静态清单会变成错的。

## 一、两张报表的分工（先搞清问的是哪张）

| 报表标识 | 名称 | 口径 | 维度 | 指标数 | 单位 |
|---|---|---|---|---|---|
| `贵金属业务分析-贵金属业务` | 贵金属业务（分产品明细） | **明细**，一行 = 一个 投资组合×产品分类×五级产品 组合 | 3 个（投资组合 / 产品分类 / 五级产品） | 25 | **元**（笔数=笔，期限=天） |
| `贵金属业务分析-整体表格` | 贵金属业务-整体情况表 | **汇总**，两个板块（规模情况 / 损益情况） | 2 个（板块 / 统计维度） | 18 | **元**（占比=%） |

> **两张表的金额单位都是「元」**，报表原始值就是元（如名义本金 `4,364,991,800` 即 43.65 亿元），
> 工具**不做任何换算**。要展示成亿元请自己 `÷1e8`，并注明「已折算为亿元」。

> 指标数与维度只要记个大概即可；确切数字以 `list_reports` 实时返回为准。

**关键差异（最容易答错的地方）**

1. **同一指标名在两张表里含义不同。** 8666 的「业务损益」是**全业务汇总口径**的一列；
   8670 的「业务损益折人民币（不含内部账）」是**逐组合明细**。合计能对上，但**不能混用**。
2. **8666 没有明细维度。** 只按「统计维度」展开（「合计」、某投资组合码值、或某产品分类），
   **不提供 投资组合×产品分类×五级产品 交叉**。要品种级明细必须用 8670。
3. **「营业净收入」「非息收入」「期末余额」「当期发生额」只在 8666。** 8670 没有这四个指标。
   反过来，「新发生-*」「存量本金」「平均持有期限」只在 8670，8666 没有。

   > ⚠️ **但「按投资组合拆营业净收入」要查 8666，不是 8670。** 这是最反直觉的一点：
   > 「投资组合」通常指向 8670，可 8666 的「统计维度」里**也列了同样那 35 个投资组合码值**。
   > 所以问「各投资组合的营业净收入」，正确报表是 **8666**（用 `p8666_section="贵金属业务损益情况"`）。
   > 工具已按「指标归属优先于维度」自动裁决，路由交给它即可；
   > 但如果你显式传了 `report="8670"`，就会得到「未命中」——**别去 8670 找营业净收入**。

4. **8666「统计维度」一列混装两套互斥分类，各行严禁相加。**
   这一列同时放了 **9 个 4 位码值类**（TGLD / ZCCS / TFHG …）和 **4 个中文产品类**
   （贵金属即远期 / 贵金属掉期 / 贵金属期权 / 其他），还有一个「合计」行。
   - 实测 13 行全加 = `598,668,964.49`，而合计行只有 `265,711,652.91`，**多出 125%**；
   - 「其他」与「ZOFS」是同一个数（`10,683,300.46`），进一步说明两套分类互相重叠；
   - **总量只能取「合计」行**；比大小只能在**同一套分类内部**比。
   - 工具返回时 `notes` 首条会带这个警告，看到就以它为准。
4. **含内部账 / 不含内部账是两套独立列，必须点名。** 只说"损益多少"不合格。
   - 8670：每个损益指标都有 `（含内部账）` 与 `（不含内部账）` 两列。
   - 8666：**不带后缀的列（业务损益 / 公允价值变动 / 评价损益 / 其他损益）就是含内部账口径**，不是"总计"。
   - 两口径的业务含义（谁含行内内部交易、哪个是对外/监管口径）用
     `describe(report="8670", field="含内部账")` 现查。
5. **行内混有小计/合计行。** 8670 有「TGLD 小计//」「合计//」，8666 有「贵金属业务损益情况/合计」。
   **不可与明细行相加或混用**；`precious_metals_breakdown` 已自动排除。

### 「金融市场部」这类说法怎么处理（重要，最容易答偏）

**贵金属报表里没有「分中心」这个维度**，也没有部门字段。所以这里与金市营收那套完全不同：

> **问「金融市场部 / 全部门 / 整个部门 / 全行」= 取全部数据，但必须按分类维度展开展示，不能只给一个总数。**

具体做法：

| 用户问法 | 正确处理 |
|---|---|
| 金融市场部的贵金属损益 / 部门整体情况 | 用 `query(report="8666")` 取全量（合计行=部门口径），**同时**按投资组合或产品分类展开 |
| 金融市场部各组合的损益 | `breakdown(metric=…, report="8670", top_n=0)` → 逐组合列全，**不要只给 top3** |
| 金融市场部的名义本金 | 合计行给总量 + 按「产品分类」或「五级产品」分类型展示明细 |
| 整个部门赚了多少 | 取 `合计//`（8670）或 `…/合计`（8666）的损益合计，并注明是**全部门汇总**口径 |

### 一问要多张表的数 → **必须拆成多次工具调用**

> ⚠️ **工具一次调用只服务一张报表，不会自动跨表。** 这是实测确认的硬约束。
> 最危险的不是报错，是**静默丢一半** —— 工具只返回得分最高的那张表的数据，
> 另一半既不返回也不提示，用户完全察觉不到。

**实测案例**：「贵金属业务整体营业净收入多少，**各组合的名义本金**分别多少」
→ 实际只返回了营业净收入（8666），**「各组合名义本金」整段被丢弃**，且无任何提示。

**正确做法**：先拆成独立子问题，各调一次，再合并成一段回答。

| 用户一句话 | 拆成 |
|---|---|
| 整体收入多少，各组合本金多少 | ① `营业净收入` → 8666　② `各投资组合的名义本金` → 8670 |
| 各组合的收入和损益对比 | ① 营业净收入 → 8666　② 损益合计 → 8670，**按组合名对齐后合并** |
| 这个月规模和收入都怎么样 | ① 期末余额/当期发生额 → 8666　② 名义本金 → 8670 |

**合并时的两条纪律**：
1. **按维度值对齐**，不要按行号对齐——两表行数、行序都不同（8666 的组合行与 8670 的明细行不是一一对应）。
2. 两表口径不同（8666 是汇总、8670 是逐产品明细），合并结果要**分别注明来源**，
   不要拼成一个看起来同源的大表。

| 哪个组合**营业净收入最高 / 最低** | **8666** | 同上，按数值排序取首尾；**负数才是亏损**，别把最小值当"亏" |
| **非息收入**各组合多少 | **8666** | 同营业净收入 |
| 即期（TGLD）的 **BUY/SELL 交易本金** | **8670** | `p8670_portfolio="TGLD"`；交易本金只在 8670 |

> 拿不准就**不传 `report`**，让工具按指标归属自动裁决（它会给出 `reason` 说明）。

**两个必须提醒用户的前提错误**（问题本身问错了，别硬答）：

1. **「盈亏」不要只看最小值。** 问「亏损最严重的是哪个」时，先把候选值筛出来看**有没有负数**。
   当前数据里营业净收入**全部为正**，此时正确回答是「**本期没有亏损的组合**」，
   而不是把数值最小的那个说成"亏损最少/亏损最严重"。**最小值 ≠ 亏损**。
2. **问「即期 vs 远期 vs 延期 vs 掉期」必须下沉到「五级产品」层，不能只答「产品分类」。**

   > ⚠️ **本节此前写错过，2026-10-22 业务方纠正。** 原文说"没有独立的即期和远期"，
   > 这是**只看粗分类得出的错误结论**。实际上五级产品里**明确有** `贵金属即期`、`贵金属远期`、`贵金属掉期`。

   两层维度必须分清：

   | 层级 | 维度 | 取值 | 能否回答「即期 vs 远期」 |
   |---|---|---|---|
   | 粗 | 产品分类 | 贵金属即远期 / 贵金属掉期 / 贵金属期货延期 / 贵金属期权 / 其他 | ❌ 即期与远期**被合并**成「贵金属即远期」 |
   | 细 | **五级产品** | `贵金属即期`、`贵金属远期`、`贵金属掉期`、`Au(T+D)延期交收` 等 | ✅ **能分开** |

   - **问「即期 / 远期 / 掉期」→ 用 `p8670_level5` 传这几个精确档位**，不要用 `p8670_category`。
   - **问「延期」→ 它不是单一档位**，而是散在一批「…延期交收」品种里：
     `Au(T+D)延期交收`、`Ag(T+D)延期交收`、`mAu(T+D)延期交收`、`Au (T+N1) 延期交收`、
     `Au (T+N2) 延期交收`、`NYAuTN06延期交收`、`NYAuTN12延期交收`、`白银延期实物交割交易`。
     答的时候要把这几档**逐档列出并汇总**，不能只挑一个。
   - **没有叫「延期」的独立档位**，但有「贵金属期货延期」这个粗分类。
   - 写法提醒：库里是「贵金属**掉**期」不是「贵金属**调**期」，用户口误时按掉期理解。

## 二、问题类型 → 工具映射

| 用户在问什么 | 用哪个工具 | 关键参数 |
|---|---|---|
| 不确定查哪张表 / 有哪些指标可选 | `precious_metals_list_reports` | 无 |
| **字段什么意思 / 维度有哪些取值 / 有没有这个指标** | `precious_metals_describe` | `report`，可选 `field`（不传则列全表目录） |
| **取某个数**（单值、某品种、某组合、某天） | `precious_metals_query` | `metric` + `report` + `report_dt` |
| **排名 / 谁最高最低 / 各组合分别多少** | `precious_metals_breakdown` | `metric` + `top_n` + `order` |
| 取不到数、换环境后异常、怀疑报表改版 | `precious_metals_probe` | `report` + `report_dt` |

**`query` vs `breakdown`**：`query` 返回符合条件的行（**含**小计/合计，适合查单值）；
`breakdown` **排除**小计/合计后排序（适合排名和构成）。**排名场景一律用 `breakdown`**。

**取「合计」总数查 `query`**，不要自己把明细加起来。8666 的合计行行键是
`贵金属业务损益情况/合计` / `贵金属业务规模情况/合计`，也可以用 `p8666_dim="合计"` 显式筛。

**不确定指标名全称时**（如"营业净收入"到底叫不叫这个），先 `describe(report=...)` 拉目录核对，
不要直接猜着传给 `metric`——叫法差一个字就会返回空。

### 维度筛选参数

> ⚠️ **参数名以工具 `input_schema` 为准**，`describe` 里查到的维度 key（`portfolio`/`product`/
> `level5`/`section`/`dim`）只用于描述，**不是可直接传的参数名**，别混用。

| 参数 | 报表 | 说明 |
|---|---|---|
| `p8670_portfolio` | 8670 | 投资组合，**4 位英文码值**，只能精确匹配，页面无中文名 |
| `p8670_product` | 8670 | 产品分类 5 项：贵金属即远期 / 贵金属掉期 / 贵金属期货延期 / 贵金属期权 / 其他 |
| `p8670_level5` | 8670 | 五级产品中文品种名（`Au99.99现货实盘`、`Ag(T+D)延期交收`） |
| `p8666_section` | 8666 | 板块：`贵金属业务规模情况` / `贵金属业务损益情况` |
| `p8666_dim` | 8666 | 统计维度：`合计`、某投资组合码值、或某产品分类中文 |

**码值/品种名的完整取值一律现查**，不要凭记忆列：
`describe(report="8670", field="投资组合")` / `field="五级产品"` / `field="产品分类"`；
`describe(report="8666", field="统计维度")`。

也可把整句传给 `metric`，工具会自动识别维度词
（「Ag(T+D)延期交收名义本金折人民币」→ 维度=五级产品:Ag(T+D)延期交收 + 指标=名义本金折人民币）。

## 三、必守规则

1. **先交代数据来源。** 每次给数值都要说明出自哪张表，用 `report_label`
   （形如 `贵金属业务分析-贵金属业务`、`贵金属业务分析-整体表格`）。**原样输出，不要改写。**
   **回答里不要提 8670 / 8666 这类报表编号**——那是技术 ID，业务人员看不懂；
   编号只出现在返回的 `report_id` 字段里，供排障用。
2. **日期以工具返回为准，不要自己编。** 未指定时默认**前一日**，`notice` 里有说明，
   **该 notice 必须转告用户**。用户指定日期就传 `report_dt=YYYY-MM-DD`。
3. **金额单位是「元」，工具不做任何换算。** 工具已按指标标注（金额=**元**、笔数=笔、期限=天、占比=%）。
   - 直接报数就用元，数值会很长（如 `4,364,991,800`），**不要因为数字大就自己改单位**。
   - 需要亿元时 **÷1e8**（不是 ÷1e4），且必须在单位里写明「亿元」，别只换数字不换单位。
   - 例：`4,364,991,800 元` → 「43.65 亿元」；写错成 ÷1e4 会变成「436,499.18 亿元」，差一万倍。
4. **含/不含内部账必须点名。** 见第一节第 4 条。
5. **小计/合计不能与明细相加。** 排名用 `breakdown`；求总数用 `query` 取合计行。
6. **只读。** 任何新增/修改/删除诉求一律拒绝并说明。
7. **答不了的如实说，不要用相近指标顶替**（见 description 中「不适用」清单与 8666 四处缺口）。

## 四、常见问法处理示例

| 用户问 | 处理 |
|---|---|
| 贵金属期权 2025-12-31 的营业净收入 | `query(metric="营业净收入", report_dt="2025-12-31", p8666_dim="贵金属期权")` → 只有 8666 有此指标 |
| Ag(T+D)延期交收名义本金折人民币 | `query(metric="Ag(T+D)延期交收名义本金折人民币")` → 自动落 8670、自动识别五级产品 |
| 哪个组合损益最高 | `breakdown(metric="损益合计（不含内部账）", report="8670", top_n=5)` |
| 各产品分类的期末余额 | `breakdown(metric="期末余额", report="8666", p8666_dim=..., top_n=0)` |
| 黄金现货实盘规模多大 | `query(metric="名义本金折人民币", p8670_level5="Au99.99现货实盘")` |
| 交易笔数多少 | `query(metric="交易笔数", report="8670")` → 单位「笔」，不是元 |
| 含内部账和不含内部账差多少 | 分别取两列再相减，**说明这是两口径之差**；8666 只有合计项有该口径 |
| 贵金属整体情况怎么样 | `query(report="8666")` 取全量后按两板块组织，或 `breakdown` 看构成 |
| 有哪些投资组合码值 | `describe(report="8670", field="投资组合")` |
| 某个指标是什么意思 | `describe(report="8670", field="含内部账")` 等，按关键词查 |

## 五、排障

取不到数时**先跑 `precious_metals_probe`**：

| probe 结果 | 含义 | 处置 |
|---|---|---|
| 字段命中数 = 指标总数、表头 1 层 | 正常 | 继续取数 |
| 字段命中数明显偏低 | 表头结构变了 | 告知用户报表可能改版，需维护字段映射 |
| 「页面打不开」 | 服务不可达或编号错 | 检查报表地址配置与编号 |
| 判定「非表格」 | 页面改成 JS 渲染或门户页 | 按 probe 提示处理，不要硬解析 |
