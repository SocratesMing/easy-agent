# 会话手动归档验证

日期：2026-11-09。设计：[会话手动归档管理](../design/2026-10-30-会话手动归档管理设计.md)。

## 实现范围

- 数据库结构版本升级至 16；SQLite / MySQL 幂等增加 `sessions.archived`。归档接口仅更新本人会话的标记，不经过通用保存或删除流程，不修改创建时间、最后活跃时间、置顶或运行租约。后续消息和元数据保存保留归档标记。
- 新增 `PUT /agent/sessions/{id}/archive`；列表默认未归档，计数未传筛选时保留全部可见会话总数语义；详情、历史透传归档状态。列表和计数共用数据库筛选，标题字面搜索发生在分页之前，归档列表按最后活跃时间和 ID 稳定排序。
- Vue 2 受管模块与 Vue 3 同步增加行归档、用户菜单归档管理、标题搜索、20 条服务端分页、取消归档与删除确认。恢复保留置顶，管理弹层不切换背景会话；同一行写入期间禁用重复操作；读取失败可重试，写入成功后的刷新失败独立反馈。
- 日常列表、归档列表、按 ID 元数据独立管理；用户版本、列表版本与删除标记阻止迟到请求回填。归档通过独立状态通知退出展示，保留会话缓存、后台生成、审批及压缩请求恢复标记。初始选择与流式重挂载尊重欢迎页选择，按 ID 入口仍可访问归档会话。
- 流式重连、快照回放、错误、用量与结束事件按所属会话写入；后台历史回填不再以日常列表成员判断会话存在。共享压缩状态补充用户版本保护。共享逻辑由 `frontend-shared/` 同步至两端。

## 浏览器验收

使用 Playwright CLI 打开两端生产构建（Vue 2 `:18090`、Vue 3 `:18091`），普通 API 透明转发至 `:18089` 的真实 FastAPI。后端使用测试配置和独立临时数据，创建专用用户及 26 条会话；没有修改用户业务会话。

两端均通过：

1. 归档当前置顶会话后从日常列表移除，回欢迎页，当前选择持久化为 `__new__`；刷新仍保持欢迎页。
2. 归档管理显示服务端计数、第一页 20 条和后续页；搜索回到第一页。点击标题不打开历史；取消归档保持弹层打开、不切换背景，恢复原置顶状态。
3. 删除取消保留目标，确认后删除且刷新列表。Vue 3 额外检查归档确认初始焦点与管理弹层 Escape 关闭。
4. 通过 `?session=<id>` 打开归档会话并读取已有消息，刷新后仍能读取；日常列表不出现该会话。
5. 生成中归档不触发前端 AbortSignal；随后注入的正文及错误不进入欢迎页。立即刷新并模拟后端仍活跃，前端后台挂载 live 流；回放、用量及结束标题没有切回目标或补回日常列表。此项使用浏览器内受控 SSE 和状态响应，归档 / 详情 / 列表仍使用真实 API，未调用外部模型。
6. Vue 2 在 1200 × 588 窗口复验弹层边界与分页可见，修正原 Element Dialog 默认上边距导致的底部裁切。
