# 指令菜单与手动压缩设计

原设计：2026-10-26；按当前代码复核：2026-11-06  
状态：已实施（2026-11-06）。两版前端、会话压缩接口、摘要适配和持久记录已落地；实际验证结果及支持边界见 [验收记录](../verification/2026-11-06-指令菜单与手动压缩验证.md)。验证包含真实 DeepAgents 图、SQLite checkpoint、DeepSeek 真实摘要调用及当前托管前端的刷新恢复。

## 1. 目标与当前基线

输入框的 `/` 面板按“指令”“技能”纵向分组，各组用标题和匹配数量隔开，不使用横向页签。指令组提供“压缩 compact”；输入查询词时过滤各组，隐藏无匹配项的组。选择后立即压缩当前会话的较早上下文，保留近期内容和可查看的原始聊天记录，不发送普通聊天消息。继续使用现有自动摘要的模型配置、提示词和保留策略；手动操作不等待自动触发阈值。

设计复核时的关键事实（实施前基线）：

- 两版 `ChatInput.vue` 的 `/` 面板目前只处理技能；Vue 2 使用内联技能 token，须保留现有草稿、附件和技能选择行为。
- [sessions/thread.py](../../easy_agent/services/sessions/thread.py) 的会话 thread 除空状态水合外，还会补齐 DB 中未同步的轮次和中断回复；对不匹配的历史会重新水合。`session_thread_active()` 同时依赖配置和实际 checkpointer，不能只判断开关。
- [summarization.py](../../easy_agent/agent/summarization.py) 根据所选模型配置键计算阈值、保留量与裁剪预算，并使用 `count_context_tokens`。主代理使用 [TurnAwareSummarizationMiddleware](../../easy_agent/agent/turn_context.py)，本轮渲染内容只用于模型请求，不应作为历史写入 checkpoint。
- [runtime.py](../../easy_agent/services/sessions/runtime.py) 已有数据库原子获取的跨副本会话流租约及续约机制。SQLite checkpoint 可按 Pod 隔离，数据库租约本身不保证请求到达持有最新 checkpoint 的实例。
- 锁定依赖为 DeepAgents 0.7.28、LangGraph 1.2.16；`pyproject.toml` 允许 DeepAgents 0.7.x 更新，私有方法不能视为稳定接口。

## 2. 交互

- 输入 `/` 显示“指令”与“技能”，指令排在前面；`/com`、`/压缩` 可筛选压缩项。技能加载失败时指令仍可用。
- 点击或方向键选择后 Enter 立即执行；避开输入法组词。只移除本次 `/查询词`，保留其余草稿、附件和技能 token。
- 新会话无历史、生成中、等待审批或当前运行模式不支持时禁用并给出原因。服务端仍须独立校验，不能信任前端状态。
- 执行期间显示 `compact · 正在压缩...`，禁止同会话重复压缩和发送；完成、跳过或失败均显示对应状态，允许失败后重试。会话切换后，结果仍归属于发起时的会话和消息位置。
- 成功记录显示在消息流中，刷新可恢复；不插入普通用户或助手消息。跳过和失败的即时状态也绑定发起时的位置；是否跨刷新保存由下述记录方案决定。
- 消息流提示带终端图标，使用 `compact · 已压缩`、`compact · 正在压缩...`、`compact · 无需压缩` 简短文案，左边界与正文对齐；详细跳过原因放在悬停提示中。

## 3. 接口与状态

已新增 `POST /agent/sessions/{session_id}/context/compact`，请求包含当前所选的模型配置键 `model`。按现有 JWT 身份和 `get_owned_session` 校验归属，并校验模型可用；禁止将客户端提供的用户或 checkpoint 标识作为信任依据。接口同步等待摘要，返回 `session_id`、`status`（`compacted` 或 `skipped`）、`message`、`reason`（跳过原因）及 `compaction`（记录 ID、锚点、时间、前后估算和模型窗口）。忙碌、待审批、不支持模式和摘要失败使用明确的项目错误响应。

消息锚点应使用稳定的消息/轮次标识及顺序，而非数组下标；需定义空历史与缺少旧 `turn_id` 的兼容处理。成功记录可作为 checkpoint 的独立状态字段，不进入 `messages`；实现时必须先把该字段加入实际图的 state schema，并验证 `aupdate_state` 可以持久化和读取。会话详情与历史读取当前以 DB 消息为权威投影，须显式合并记录，不能假设它们会自动读取 checkpoint。若选择将记录写入业务库，需设计与 checkpoint 写入之间的失败恢复；跳过/失败是否持久化及其失败语义也应明确，不能声称已实现。

占用环可展示保存后有效上下文加基础系统提示的 token **估算**，响应须标明估算口径和模型窗口；动态提示、工具 schema 等可能未计入，不替代供应商 usage。累计输入、输出等实际统计保持现有口径，后续真实 usage 到达后恢复使用真实值。相关统计设计应与 [Token 用量统计设计](./2026-10-30-Token用量统计设计.md) 对齐。

跳过压缩也须返回当前有效上下文估算，不能恢复压缩前用量。压缩后的本地预检回复如果明确 usage 为零，继续显示压缩估算并计入新增文本估算；发送等待阶段同样保留估算，不能因进入 streaming 状态恢复旧用量。新模型调用的 `token_usage` 到达时立即恢复供应商口径，不必等待回答完成。

同步请求设置合理超时。客户端超时或断线不代表服务端一定未提交；刷新或重试前应读取权威状态，避免重复压缩。实现需设计请求标识和去重/结果查询，或明确提供等价的可靠恢复机制；不能只依赖前端禁用按钮。

## 4. 后端流程与边界

1. 校验身份、会话归属、模型及实际运行模式；获取与聊天、审批恢复共用的会话租约，失败时返回忙碌。
2. 在租约内检查当前图状态、DB 记录及所有待处理任务/审批；工具、审批、子图或无法可靠判断的挂起状态拒绝。在取得独占租约且确认无 live run 后，允许仅剩无中断、无子图的 `model` 续跑状态（生成取消或失败可能留下该状态），提交到终止节点时一起结束，不恢复主模型。长时间摘要期间续约，租约丢失时停止并禁止提交；必须验证释放和续约不会影响接管后的任务。现有租约以实例为 owner，不能单凭一次检查证明写入时仍持有租约；实现须处理过期、同实例重入与检查到写入之间的竞态，必要时增加每次操作的令牌及提交保护。
3. 复用或抽取 `plan_turn()` 的历史对齐逻辑，得到与下一次聊天一致的有效上下文：包含空 checkpoint 水合、缺失轮次、半截回复及不匹配处理。不能调用会删除旧 thread 的现成分支后再冒险摘要；摘要失败必须保留原状态。旧消息缺少轮次 ID 时需要稳定映射，并验证下一轮不会因对齐失败丢弃新摘要。
4. 在适配层使用当前模型配置键、用户/会话绑定的 backend 和与主代理一致的 token counter，读取既有摘要事件并计算安全分割位置；保留工具调用及结果配对。针对历史使用正确的消息视图，不把过期 `turn_context` 重新注入历史，也不把本轮临时内容写入持久消息。
5. 在局部变量中完成媒体处理、归档和摘要；检查显式失败结果。失败不提交事件；归档文件可能已产生，须设计清理或允许孤立文件。输入预算遵循当前配置；框架按 human 边界裁剪长工具链返回空输入时，改用限定预算的历史文本视图，保留开头目标和末尾工具结果（含无换行的长结果）。仅裁剪摘要输入视图，checkpoint 和归档仍保留完整原文与工具配对。
6. 通过实际编译图和公开 checkpoint API 提交摘要事件、归档 ID、必要的水合消息及成功记录，验证保存后的事件和无待执行任务，再返回成功。终止节点须按实际图验证，不能硬编码旧实验节点。写入后读取失败时结果为未知，客户端应按请求标识恢复，不能宣称未写入。

`agent.session_thread` 关闭、使用 `PersistentMemorySaver` 回退等使 `session_thread_active()` 为 false 的情况不支持本功能。按 Pod 隔离 checkpoint 的部署中，必须保证操作和后续聊天访问同一权威 checkpoint；若无法证明路由与状态归属，拒绝压缩而非将空 checkpoint 当新会话水合。共享或其他 saver 的支持范围以实际 `session_thread_active()`、部署配置及集成测试为准。

摘要框架的 `_` 方法、事件格式和 cutoff 换算均封装在适配层，基于锁定版本的真实图验证；不得修改共享中间件实例。原始 `messages` 和 UI 历史保留，下一轮使用摘要事件与未覆盖消息；不调用完整 `awrap_model_call()` 触发额外主模型回答。自动压缩关闭时手动压缩的行为需明确：本设计允许用户显式触发，但须单独定义可用的 keep 和预算，不能直接沿用关闭时被抬高到不可达的参数。

## 6. 验收与验证

1. 两版前端及侧边栏支持鼠标、键盘、中文输入法、搜索、技能加载失败、草稿和附件保留；会话切换及请求超时不串状态。

3. 覆盖空 checkpoint 水合、DB 追加轮次、取消后的半截回复、旧消息无 `turn_id`、历史不匹配以及已有摘要再次压缩；验证下一轮不会重新水合而丢失摘要。
4. 覆盖生成、审批恢复与压缩互斥，跨实例竞争、租约过期/续约失败、取消和重复请求；验证失败不覆盖旧状态及未知提交结果可恢复。
5. 验证归档/媒体失败、模型错误、checkpoint 写入及读取失败、无可压缩内容、关闭自动压缩、不同模型窗口、会话隔离和不支持的部署模式。
6. 刷新后成功记录位于正确消息位置；估算与真实 usage 标识清晰，原历史仍可查看。完成后记录实际依赖版本和验收结果。

## 7. 2026-11-12 兼容性契约与官方工具选型复核

### 安装、探测与升级

- `pyproject.toml` 显式依赖 `deepagents==0.7.28`、`langgraph==1.2.16`，与适配层的已验证版本集合一致；`uv.lock` 通过 `uv lock --offline` 正规更新，未升级其他框架包。推荐 `uv sync --frozen --group dev`；通过包元数据安装也受相同精确版本约束。
- `manual_compaction.compatibility_reason()` 统一检查上述两个包的版本信息和所用 9 个私有方法的可调用性。精确版本是支持条件，方法存在检查只负责识别损坏/被修改的安装，不意味着支持其他版本或已证明所有签名兼容。
- 应用启动不因手动压缩不可用而整体退出；压缩状态查询和执行前按需探测。`GET .../context` 返回 `supported=false` 及具体原因，`POST .../context/compact` 在建图、摘要、归档前返回相同原因的 409。直接调用适配层也在访问 backend 前拒绝；无需摘要时的估算同样遵守兼容性边界。部署模式、独立 checkpoint 文件等限制继续生效。
- 已提交请求仍优先回读权威结果，不因环境变化丢失同 ID 结果恢复能力。不兼容环境不允许启动新的摘要；本次未扩大 worker、实例或 saver 支持范围。
- 升级时须同步修改依赖、锁文件和验证集合，并重跑实际编译图测试（事件、cutoff、工具配对、归档、终止、重启后下一轮输入），不能仅放宽版本判断。

### 官方 `SummarizationToolMiddleware` 对照及决定

本次原型使用本机 DeepAgents 0.7.28 的公开 `tools[0].ainvoke()` 及真实 `ToolRuntime`，使用假模型和临时 backend，不调用工具的 `_arun_compact` 或恢复整个 agent 回答流程。可执行依据在 `tests/services/test_compaction_official_tool.py`。

| 场景 | 官方工具公开入口结果 | 当前产品要求/处理 |
| --- | --- | --- |
| 自动压缩关闭 | 受自动 trigger 的准入门槛影响，原型返回无需压缩 | 独立手动 keep/预算，可主动摘要 |
| 无 reported usage / 低于 token 门槛 | 即使估算历史很长，也不生成摘要 | 显式操作按有效历史决定 |
| 空摘要 / “过长无法摘要”哨兵 | 仍构造成功事件及成功 ToolMessage | 拒绝空摘要；长工具链先降级摘要，仍无效则拒绝 |
| 归档返回 `None` | 仍构造成功事件 | 不提交新事件和成功记录 |
| 直接执行、再次压缩 | 可只调用摘要模型；结果带 ToolMessage；沿用已有归档 ID/路径 | 保持无额外主模型回答，成功记录独立于 messages，每次独立归档 |

结论：保留当前集中适配层。官方工具确实存在且可独立执行，但其准入和失败语义不满足本产品；本次没有通过私有工具入口绕过门槛，也没有通过修改共享中间件来伪装等价迁移。媒体预处理和长工具链降级继续由现有适配层及既有回归覆盖；本次官方原型不声称已穷尽所有媒体/工具链输入。

### 互斥与失败恢复

保留共用业务库租约、幂等记录、运行中请求合并和提交围栏。`tests/services/test_compaction_lifecycle.py` 新增真实编排层验证：续约失败/接管取消准备工作；摘要前超时不提交；提交前取消由围栏拒绝；提交中超时仍等待实际写入完成再释放占用，同 ID 可回读且不再次摘要；聊天/resume 使用的 `acquire_stream` 与压缩占用互斥。测试通过事件屏障控制竞争窗口，缩短的心跳/超时仅作用于测试。
