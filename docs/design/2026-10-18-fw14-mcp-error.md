## 1. 审计结论（mcp-server）

扫描 `mcp-server/easy_mcp_server/**` 的 `json.dumps`、`try/except`、`"error"`
与 `ToolError` 用法后，结论分三层：

1. **显式“异常 → JSON 文本成功”包装：0 处。**
   `market` 的三个工具都直接 `return dict/list`，没有 `_safe()` 一类兜底把
   `{"error": ...}` 当正常结果返回。
2. **但失败语义仍不完整。** 未捕获异常由 FastMCP（`mcp==1.29.1`）兜底：
   `Tool.run` 把任意 `Exception` 包成
   `ToolError(f"Error executing tool {name}: {e}")`，最终 `isError=true`，
   但错误文本包含**原始异常**——可能带 DSN/host/密码片段，且对模型是内部噪音。
   同时“空结果”与“失败”的边界没有文档化。
3. **审计点名的真正 JSON 成功包装在其它位置。**
   主仓 `mcp/jmfx_mcp_server.py` 的 `_safe()` / `_envelope()`（约 691-707、
   723-737 行）把异常写进 `shape=text` 的 JSON 信封并作为成功结果返回；该文件
   不属于本任务允许改动范围（仅 `mcp-server/`），列入“未做项”。

### structuredContent 现状

审计建议中的“补 structuredContent”在 mcp-server 上**已由 FastMCP 自动满足**：
`mcp==1.29.1` 会依据返回类型注解生成 `outputSchema`，并在
`CallToolResult.structuredContent` 中返回结构化结果（dict 原样、list 包在
`result` 字段下）。本次不改变返回形状，只把该行为显式化并加测试锁定。

## 2. 错误契约

### 2.1 对外格式

失败时工具抛
`mcp.server.fastmcp.exceptions.ToolError("<code>: <中文说明>")`，FastMCP 输出：

```json
{
  "content": [{"type": "text", "text": "Error executing tool <name>: <code>: <中文说明>"}],
  "isError": true
}
```

- `isError=true`，`structuredContent=null`；
- `Error executing tool <name>: ` 前缀由 FastMCP 统一添加，错误码紧随其后；
- 文本中**不含**异常类型、`repr`、堆栈、SQL、DSN、host、密码、API Key；
- 错误码稳定、面向客户端分支；中文说明面向模型/用户，可随时调整。

### 2.2 错误码

| 错误码 | 触发 | 对外说明 |
| --- | --- | --- |
| `market_quotes_unavailable` | `market_quotes` 查询/格式化异常 | 行情数据暂时不可用，请稍后重试 |
| `market_positions_unavailable` | `market_positions` 查询/格式化异常 | 持仓数据暂时不可用，请稍后重试 |

### 2.3 成功 / 空结果

- 查询成功：`isError=false`，`structuredContent` 有值；
- **空结果是合法成功**：`ask_market` 返回 `{"quotes": [], "answer": "暂无匹配的行情数据。"}`，
  `isError=false`；不用错误文案冒充空结果，也不用空结果掩盖失败。
- 身份缺失由鉴权中间件在进入工具前拦截（HTTP 401），不在工具错误契约内。

### 2.4 原始异常只进日志

`easy_mcp_server/errors.py::tool_failure()`：

1. `logger.error` 记录工具名、错误码、异常类型与脱敏后的异常文本；
2. `redact()` 处理 `password/passwd/pwd/secret/token/api_key=...`、
   `Authorization: Bearer <token>`、`MYSQL_PASSWORD` 的字面值；
3. 日志单行化并截断到 500 字符，避免日志注入与超长刷屏；
4. 返回 `ToolError(code: message)`，调用方 `raise ... from None`，
   原始异常链不会进入 FastMCP 响应。

## 3. structuredContent

`market/server.py` 的三个工具都显式声明 `@mcp.tool(structured_output=True)`，
锁定结构化输出行为（若未来返回注解不可序列化，FastMCP 会直接报错而不是静默降级）。

| 工具 | 返回注解 | `structuredContent` 形状 | 文本 `content` |
| --- | --- | --- | --- |
| `ask_market` | `dict[str, Any]` | 原 dict：`category` / `quotes` 或 `positions` / `answer` | 同一 dict 的 JSON 文本 |
| `get_latest_quotes` | `list[dict[str, Any]]` | `{"result": [quote, ...]}` | 每行一个 `TextContent`（FastMCP 1.x 兼容行为） |
| `get_my_positions` | `list[dict[str, Any]]` | `{"result": [position, ...]}` | 每行一个 `TextContent` |

兼容性：未改动三个工具的返回形状、字段名和文本序列化逻辑，因此旧调用方拿到的
`content` 文本与修改前一致；`structuredContent` 是新增的并行通道（此前已由
FastMCP 自动生成，本次通过显式开关与测试把它固化为契约）。

未引入 Pydantic 输出模型：真实 MySQL 行含 `datetime` / `Decimal`，严格
`str`/`float` 字段会在输出校验阶段拒绝合法数据；当前保留 `Any` 级别的
`outputSchema`，换取与线上数据类型的兼容。

## 4. 实现

- `easy_mcp_server/errors.py`（新增）

- 测试

    `structuredContent` 形状、空结果仍成功；
  - `tests/test_errors.py`：脱敏、日志、对外文案只含错误码。

## 6. 风险与限制

- **FastMCP 前缀**：客户端看到的错误文本仍带 `Error executing tool <name>: `，
  这是库的固定行为；错误码在其后可稳定解析。
- **未做 OAuth**：审计另列 FW-10（OAuth/超时透传），与本次错误语义无关，未触碰。
- **未改主仓 `mcp/jmfx_mcp_server.py`**：其 `_safe()` 仍是 JSON 文本成功语义，
  需在允许改主仓 `mcp/` 的任务中单独修。
- **未引入严格输出模型**：见 §3 的 `datetime`/`Decimal` 兼容性取舍。
- **错误文案为中文**：与 market 现有返回一致；错误码是稳定的机器接口。
