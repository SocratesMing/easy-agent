# frontend-vue2 前端配置说明

> 适用目录：`frontend-vue2/`（Vue 2.7 + @vue/cli 5 + webpack）
> 配置入口：**环境/后端地址 → `vue.config.js`；应用名称与开关 → 各 Vue 组件内常量**
> 说明：原 `src/config.js` 与 `scripts/generate-runtime-config.sh` 已移除，不再有「运行期配置」概念。

## 1. 总体思路：相对路径 + 同源

前端**所有接口一律使用相对路径**（`/agent/...`），不拼接后端域名：

| 环境 | 请求如何到达后端 | 是否跨域 |
| --- | --- | --- |
| 开发 / 联调（webpack-dev-server） | `vue.config.js` 的 `devServer.proxy` 把 `/agent` 转发到对应环境后端 | 否（浏览器只看到 dev server） |
| 生产 | 后端同源托管 `dist/`，或 Nginx 反代 `/agent` 到后端 | 否 |

因此：**后端地址只在 `vue.config.js` 维护一处**，前端代码里不会再出现绝对地址，也没有跨域配置需求。

## 2. 环境与后端地址（`vue.config.js`）

```js
const PROXY_TARGETS = {
  dev:  'http://localhost:8000',
  test: 'http://192.168.1.100:8007',
  prod: 'http://192.168.1.200:8000',
  win:  'http://127.0.0.1:8000',
}

const AGENT_ENV = process.env.VUE_APP_AGENT_ENV || (process.platform === 'win32' ? 'win' : 'dev')
const PROXY_TARGET = process.env.VUE_APP_PROXY_TARGET || PROXY_TARGETS[AGENT_ENV] || PROXY_TARGETS.dev
```

- 当前环境由 `.env.<mode>` 里的 `VUE_APP_AGENT_ENV` 决定（Vue CLI 会先加载 `.env.<mode>`，再读取 `vue.config.js`）。
- 需要临时指向别的后端时，直接覆盖：`VUE_APP_PROXY_TARGET=http://10.0.0.5:8000 npm run dev`。
- 代理配置：

```js
devServer: {
  proxy: {
    '/agent': {
      target: PROXY_TARGET,
      changeOrigin: true,
      onProxyRes(proxyRes) { proxyRes.headers['cache-control'] = 'no-cache' }, // SSE 不缓存
    },
  },
}
```

> 注意：`devServer` 必须是 `vue.config.js` 的**顶层字段**（放在 `configureWebpack` 内不会生效）。

## 3. 各环境 `.env.<mode>`

`.env.<mode>` 只保留「当前是哪套环境」这一标记，用于 `vue.config.js` 选择代理目标；
**不再配置 `VUE_APP_API_BASE_URL` 等地址类变量**。

| 文件 | 内容 | 何时加载 |
| --- | --- | --- |
| `.env.dev` | `VUE_APP_AGENT_ENV=dev` | Linux/macOS 下 `npm run dev` |
| `.env.test` | `VUE_APP_AGENT_ENV=test` | `AGENT_ENV=test npm run dev` |
| `.env.prod` | `VUE_APP_AGENT_ENV=prod` | `npm run build`（默认 prod） |
| `.env.win` | `VUE_APP_AGENT_ENV=win` | Windows 平台或 `AGENT_WIN=true` |

模式选择逻辑在 `scripts/env-mode.mjs`（平台 + `AGENT_ENV` → mode），`scripts/run-vite.mjs`
用它传 `--mode <mode>` 给 `vue-cli-service`，并在启动横幅中打印实际代理目标。

## 4. 应用级常量（定义在 Vue 组件内）

| 常量 | 定义位置 | 说明 |
| --- | --- | --- |
| `APP_TITLE = 'Easy Agent'` | `src/App.vue`、`src/components/SessionList.vue`、`src/components/Welcome.vue` | 应用名称；`App.vue` 在 `mounted` 中写入 `document.title` |
| `APP_WELCOME_TITLE` | `src/App.vue`、`src/components/Chat.vue` | 首页欢迎语；`Chat.vue` 中作为 prop 默认值 |
| `LOGIN_PAGE_ENABLED` | `src/App.vue` | 登录页开关，见第 5 节 |
| `PASSWORDLESS_LOGIN_ENABLED` | `src/App.vue` | 免密登录开关，见第 6 节 |

运行期仍可被后端覆盖：`GET /agent/auth/config` 返回的 `app_welcome_title` 会在
`applyAgentConfig()` 中覆盖欢迎语（其余 `win` / `agent_env` 字段此前只是写入、无人读取，已一并删除）。

## 5. 登录页开关 `LOGIN_PAGE_ENABLED`（`src/App.vue` 常量）

用途：控制「是否显示登录 / 注册页」。

| 取值 | 行为 |
| --- | --- |
| `true` | 显示 `Welcome` 登录 / 注册页（免密登录不参与） |
| `false`（**当前配置：登录页关**） | 不显示登录页，统一走免密登录；免密失败时显示「未授权访问」提示页 |

## 6. 免密登录开关 `PASSWORDLESS_LOGIN_ENABLED`（`src/App.vue` 常量）

用途：控制「是否由前端模拟登录用户信息直接免密登录」。
**该登录方式用于「登录页关」的场景**：仅当 `LOGIN_PAGE_ENABLED=false` 且本开关为 `true`
时才会发起免密登录；登录页开启时一律走登录页，不发起免密请求。

> 说明：本开关只影响前端是否发起免密登录请求，后端 `POST /agent/auth/login-passwordless`
> 接口本身不受影响（仍可被其它系统调用）。

### 登录身份与用户资料的取值来源

免密登录时**不调用 `loadUserProfile`**，登录身份与用户资料都来自外部门户写入的
`localStorage`（键前缀 `system:share:`）：

| 用途 | localStorage 键 | 缺省值 |
| --- | --- | --- |
| 登录账号（接口 `username`） | `system:share:loginId` | `demo` |
| IAM 员工号（接口 `user_id`） | `system:share:iamEmpLoginNo` | `demoid` |
| 姓名 → `userProfile.username` | `system:share:name` | 回落为登录账号 |
| 所属机构 → `userProfile.organization_id` | `system:share:bankName` | 空 |
| 登录账号 → `userProfile.email` | `system:share:loginId` | 空 |

流程（`handlePasswordlessLogin()`）：

1. 读取上述共享存储，缺失时使用默认值；
2. 调用 `POST /agent/auth/login-passwordless`，请求体 `{ username, user_id }`
   （用户已存在直接登录，不存在则自动注册后登录）；
3. 用共享存储中的姓名 / 机构 / 登录账号填充 `userProfile` 并进入主界面。

> 注：后端以 token 中的用户名作为数据归属（会话、工作区、记忆等），
> `userProfile` 的三个字段仅用于界面展示。

### 登录方式（按登录页开关区分）

| `LOGIN_PAGE_ENABLED` | 登录方式 |
| --- | --- |
| `false`（**当前配置**）+ 免密开 | 免密登录：前端模拟用户信息 → 后端免密接口；失败显示「未授权访问」 |
| `false` + 免密关 | ⚠️ 无任何登录入口（配置错误，启动时控制台打印告警） |
| `true` | 显示登录 / 注册页，账号密码登录（`loadUserProfile` 加载资料），不发起免密请求 |

启动时控制台会打印当前生效值，便于部署核对：

```
[登录] 登录页=关闭 | 免密登录=开启
```

## 7. 构建与部署

```bash
npm run dev      # 开发服务器（自动按环境代理 /agent）
npm run build    # 产物输出到 dist/
npm run serve    # 静态托管 dist/（会先打印部署提示）
```

生产部署的两种正确姿势：

1. **后端托管（推荐）**：让 FastAPI 指向本目录产物（`frontend-vue2/dist`），访问 `http://<backend>:<port>/`
   即为同源，前端相对路径请求直接命中后端。
2. **Nginx 反代**：`/` 指向 `dist/`，`/agent` 反代到后端；SSE 需关闭缓冲
   （`proxy_buffering off; proxy_read_timeout 3600s;`）。

> ⚠️ 直接用 `serve -s dist/` 且后端在另一个端口时，接口会打到静态服务器自身端口而 404
> —— 这是「同源」策略的必然要求，`npm run serve` 会给出提示。

## 8. 与 Vue 3 版（`frontend/`）的差异

- 本目录使用 Vue CLI 5 + webpack，Vue 3 版使用 Vite。
- 本目录已改为「相对路径 + 开发代理」；Vue 3 版仍保留 `src/config.js` 与
  `scripts/generate-runtime-config.sh` 的运行期配置机制，两者互不影响。
