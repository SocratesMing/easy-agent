# frontend-vue2 前端配置说明

> 适用目录：`frontend-vue2/`（Vue 2.7 + @vue/cli 5 + webpack）
> 配置入口：**环境/后端地址 → `vue.config.js`；应用名称、登录方式等 → 运行时配置 `configureEasyAgent()`（独立应用在 `src/standalone/adapter.js`）**
> 说明：原 `src/config.js`（读 `window.__RUNTIME_CONFIG__`）已无引用并删除；`docker/entrypoint.sh` 仍会写出 `dist/runtime-config.js`，但 Vue 2 基线的 `index.html` 从未加载它。

## 1. 总体思路：相对路径 + 同源

前端**所有接口一律使用相对路径**（`/agent/...`），不拼接后端域名：

| 环境 | 请求如何到达后端 | 是否跨域 |
| --- | --- | --- |
| 开发 / 联调（webpack-dev-server） | `vue.config.js` 的 `devServer.proxy` 把 `/agent` 转发到对应环境后端 | 否（浏览器只看到 dev server） |
| 生产 | 后端同源托管 `dist/`，或 Nginx 反代 `/agent` 到后端 | 否 |

因此：**后端地址只在 `vue.config.js` 维护一处**，前端代码里不会再出现绝对地址，也没有跨域配置需求。

## 2. 环境与后端地址（`vue.config.js`）

```js
const PROXY_TARGETS = {
  dev:  'http://localhost:8080',
  test: 'http://192.168.1.100:8007',
  prod: 'http://192.168.1.200:8080',
  win:  'http://127.0.0.1:8080',
}

const AGENT_ENV = process.env.VUE_APP_AGENT_ENV || (process.platform === 'win32' ? 'win' : 'dev')
const PROXY_TARGET = process.env.VUE_APP_PROXY_TARGET || PROXY_TARGETS[AGENT_ENV] || PROXY_TARGETS.dev
```

- 当前环境由 `.env.<mode>` 里的 `VUE_APP_AGENT_ENV` 决定（Vue CLI 会先加载 `.env.<mode>`，再读取 `vue.config.js`）。
- 需要临时指向别的后端时，直接覆盖：`VUE_APP_PROXY_TARGET=http://10.0.0.5:8000 npm run dev`。
- 代理配置：

```js
devServer: {
  proxy: {
    '/agent': {
      target: PROXY_TARGET,
      changeOrigin: true,
      onProxyRes(proxyRes) { proxyRes.headers['cache-control'] = 'no-cache' }, // SSE 不缓存
    },
  },
}
```

> 注意：`devServer` 必须是 `vue.config.js` 的**顶层字段**（放在 `configureWebpack` 内不会生效）。

## 3. 各环境 `.env.<mode>`

`.env.<mode>` 只保留「当前是哪套环境」这一标记，用于 `vue.config.js` 选择代理目标；
**不再配置 `VUE_APP_API_BASE_URL` 等地址类变量**。

| 文件 | 内容 | 何时加载 |
| --- | --- | --- |
| `.env.dev` | `VUE_APP_AGENT_ENV=dev` | Linux/macOS 下 `npm run dev` |
| `.env.test` | `VUE_APP_AGENT_ENV=test` | `AGENT_ENV=test npm run dev` |
| `.env.prod` | `VUE_APP_AGENT_ENV=prod` | `npm run build`（默认 prod） |
| `.env.win` | `VUE_APP_AGENT_ENV=win` | Windows 平台或 `AGENT_WIN=true` |

模式选择逻辑在 `scripts/env-mode.mjs`（平台 + `AGENT_ENV` → mode），`scripts/run-vite.mjs`
用它传 `--mode <mode>` 给 `vue-cli-service`，并在启动横幅中打印实际代理目标。

## 4. 运行时配置（`configureEasyAgent`）

业务代码已收敛为受管模块 `src/packages/easyAgent/`（外网独立应用、内网宿主路由页面、AI 侧边栏 SDK
共用同一份源码），原来写死在 `App.vue` / `SessionList.vue` / `Welcome.vue` / `Chat.vue` 里的
应用名称、欢迎语、登录开关全部改为运行时配置，由适配器在页面渲染前传入：

| 场景 | 适配器 | 说明 |
| --- | --- | --- |
| 外网独立应用 | `src/standalone/adapter.js` | 读构建期环境变量，保留原默认行为 |
| 内网宿主路由页面 | 宿主的 `src/integrations/easyAgent.js` | 模板见 `integration/host-template/` |
| AI 侧边栏 SDK | `src/sdk/index.js`（`init(options)`） | 选项见 `docs/AI侧边栏SDK集成指南.md` |

字段的完整说明见 `integration/README.md`「适配合同」。独立应用相关的几项：

| 字段 | 独立应用取值 | 说明 |
| --- | --- | --- |
| `app.title` | `Easy Agent` | 应用名称；`app.setDocumentTitle=true` 时写入 `document.title` |
| `app.welcomeTitle` | `Easy Agent，让工作化繁为简` | 首页欢迎语；后端 `/agent/auth/config` 的 `app_welcome_title` 仍会在运行期覆盖 |
| `auth.loginPage` | `VUE_APP_LOGIN_PAGE_ENABLED !== 'false'` | 见第 5 节 |
| `auth.urlLogin` | `true` | 地址栏 `?username=&user_id=` 免密直登 |
| `auth.signIn` | 登录页关闭时为门户免密登录 | 见第 6 节 |

## 5. 登录页开关 `VUE_APP_LOGIN_PAGE_ENABLED`（构建期环境变量）

用途：控制「是否显示登录 / 注册页」（对应运行时配置 `auth.loginPage`）。

| 取值 | 行为 |
| --- | --- |
| 未设置 / 其他值（默认） | 显示 `Welcome` 登录 / 注册页（门户免密登录不参与） |
| `false` | 不显示登录页，走门户免密登录；免密失败时显示「未授权访问」提示页 |

## 6. 门户免密登录（登录页关闭时）

实现：`src/standalone/adapter.js` 的 `portalSignIn()`，作为 `auth.signIn` 交给模块。
业务模块本身不读 `system:share:*`，这些键只在适配器里读取（内网宿主同理，在宿主适配器里读取）。

> 说明：后端 `POST /agent/auth/login-passwordless` 接口本身不受前端开关影响（仍可被其它系统调用）。

### 登录身份与用户资料的取值来源

免密登录时**不调用 `/agent/auth/profile`**，登录身份与展示资料都来自外部门户写入的
`localStorage`（键前缀 `system:share:`）：

| 用途 | localStorage 键 | 缺失时 |
| --- | --- | --- |
| 登录账号（接口 `username`） | `system:share:loginId` | 不登录，显示「未授权访问」 |
| IAM 员工号（接口 `user_id`） | `system:share:iamEmpLoginNo` | 不登录，显示「未授权访问」 |
| 姓名 → 展示用户名 | `system:share:name` | 回落为登录账号 |
| 所属机构 → `organization_id` | `system:share:bankName` | 空 |
| 登录账号 → `email` | `system:share:loginId` | 空 |

> 变化（2026-10-30）：原来身份缺失时会自动用 `demo / demoid` 免密登录，嵌入内网后会让所有缺少身份的
> 访问落到同一个演示账号上。现在默认不回落；本地演示需要时显式设置
> `VUE_APP_PASSWORDLESS_DEMO_FALLBACK=true`（只在外网开发配置里使用）。

流程：

1. 读取上述共享存储，缺少登录账号或员工号时直接返回「未登录」；
2. 调用 `POST /agent/auth/login-passwordless`，请求体 `{ username, user_id }`
   （用户已存在直接登录，不存在则自动注册后登录）；
3. 用共享存储中的姓名 / 机构 / 登录账号作为展示资料进入主界面。

> 注：后端以 token 中的用户名作为数据归属（会话、工作区、记忆等），展示资料的三个字段仅用于界面。

### 登录方式

| `VUE_APP_LOGIN_PAGE_ENABLED` | 登录方式 |
| --- | --- |
| `false` | 门户免密登录；身份缺失或失败显示「未授权访问」；401 时回到「未授权访问」（独立应用不自动续期） |
| 默认 | 显示登录 / 注册页，账号密码登录（`/agent/auth/profile` 加载资料），不发起门户免密请求；另支持 URL 免密直登 |

启动时控制台会打印当前生效值，便于部署核对：

```
[登录] 模式=standalone | 登录页=关闭 | 适配器登录=开启
```

## 7. 构建与部署

```bash
npm run dev      # 开发服务器（自动按环境代理 /agent）
npm run build    # 产物输出到 dist/
npm run serve    # 静态托管 dist/（会先打印部署提示）
```

生产部署的两种正确姿势：

1. **后端托管（推荐）**：让 FastAPI 指向本目录产物（`frontend-vue2/dist`），访问 `http://<backend>:<port>/`
   即为同源，前端相对路径请求直接命中后端。
2. **Nginx 反代**：`/` 指向 `dist/`，`/agent` 反代到后端；SSE 需关闭缓冲
   （`proxy_buffering off; proxy_read_timeout 3600s;`）。

> ⚠️ 直接用 `serve -s dist/` 且后端在另一个端口时，接口会打到静态服务器自身端口而 404
> —— 这是「同源」策略的必然要求，`npm run serve` 会给出提示。

## 8. 与 Vue 3 版（`frontend/`）的差异

- 本目录使用 Vue CLI 5 + webpack，Vue 3 版使用 Vite。
- 本目录已改为「相对路径 + 开发代理」；Vue 3 版仍保留 `src/config.js` 与
  `scripts/generate-runtime-config.sh` 的运行期配置机制，两者互不影响。
